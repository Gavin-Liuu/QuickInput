# QuickInput 已知限制与使用边界说明 (Known Limitations)

## 1. 系统权限与 UIPI (用户界面特权隔离)
- **Windows UIPI 限制**: 标准权限运行的程序无法向具有管理员权限（以管理员身份运行）的目标窗口注入按键消息或调用 `SendInput`。
- **应对方案**: QuickInput 内置了目标特权探测器（`is_target_elevated`）。当检测到目标软件为管理员权限时，状态栏将主动发出警告，提示用户“以管理员身份运行 QuickInput”以获得完整的注入权限。

## 2. 独占全屏 Direct3D / OpenGL 游戏
- 部分使用 DirectInput 或独占全屏 (Exclusive Fullscreen) 运行的三维游戏会跳过 Windows 消息队列并强行抢占鼠标与键盘。
- **应对方案**: QuickInput 适用于日常桌面窗口、窗口化全屏 (Borderless Window) 或各类专业办公/标注软件，独占全屏游戏不在本工作台的适用范围内。

## 3. 宏录制中鼠标坐标的脆弱性
- 虽然系统支持鼠标坐标动作（`mouse` 步骤），但坐标依赖特定的屏幕分辨率、窗口大小及显示器缩放比例（DPI）。如果目标窗口被移动或改变尺寸，基于绝对坐标的宏可能会点击错误位置。
- **最佳实践**: 优先录制与使用键盘按键、Tab、回车及快捷键组合（如 `Ctrl+S`, `Ctrl+N`），减少对鼠标绝对坐标的依赖。

## 4. 剪贴板大文件与特殊格式
- `paste` 步骤使用 Windows 纯文本格式 (`CF_UNICODETEXT`) 备份与恢复。如果用户原先在剪贴板中复制了复杂的带格式富文本（如 Word 表格或带有特殊 OLE 对象的图形），在恢复时可能会降级为纯文本。

## 5. Linux Wayland 会话限制
- Linux Wayland 协议的安全架构原生禁止客户端注入按键到其他客户端。当前阶段在 Linux 上推荐使用 X11 会话，或配置 `/dev/uinput` 访问权限。

## 6. 中文输入法 (IME) 与按键录制边界说明
- **物理按键 vs 组合字符**: 低级键盘钩子 (`WH_KEYBOARD_LL`) 工作在系统输入法前端，直接拦截用户的物理键盘按键（Virtual Keys）。当中文输入法激活时，用户键入的拼音英文字母会首先被输入法框架拦截组词，低级钩子无法预测用户何时按空格上屏或选择第几个候选字。
- **最佳实践**:
  1. 录制纯快捷键（如 `Ctrl+S`, `Alt+F4`, `Tab`, `Enter` 等）或英文标识符时，直接使用物理按键录制。
  2. 针对中文短语、长句子或多行模板文本，推荐在录制器中使用专门提供的“**文本 / 粘贴捕获**”功能，直接输入或粘贴文本，生成稳健的 `paste` 或 Unicode `text` 步骤。

## 7. 宏录制目标窗口锁定与前台切换过滤
- 录制器采用显式的三步录制模式，并强制执行**目标窗口过滤**。
- 录制过程中，只有目标窗口处于前台时产生的物理击键才会被记录；当用户切换到其他软件或操作 QuickInput 自身界面时，按键将被自动丢弃并显示黄色警告提示，避免误录隐私或跨程序误操作。

## 8. 窗口生命周期与托盘退出规范
- 点击主面板 Windows 原生标题栏的关闭按钮 `×` 或按 Alt+F4 默认执行**隐藏到系统托盘**，保持全局热键和后台常驻。
- **彻底退出程序**: 用户只需右键点击桌面右下角系统托盘中的 QuickInput 图标，选择“**退出程序**”，系统将注销全局热键、停止宏录制器与宏执行线程、安全保存当前配置并彻底清理进程，保证无后台僵尸残留。
