# 通用快捷输入工作台产品化任务书

## 0. 任务说明

你将基于本仓库现有的中国象棋悬浮输入键盘 Demo，将其扩展为 Windows 平台的通用快捷输入工作台。

产品不是单纯的虚拟键盘，而是一个可以由用户自行配置的“悬浮动作面板”：用户点击按钮后，可以向当前目标软件输入文本、发送按键、执行组合键、粘贴模板、运行多步骤宏，并可以一键切换不同场景的键盘布局。

第一阶段只要求 Windows 可用，未来需要能够扩展到 macOS 和 Linux。普通用户不应编辑代码或 JSON，应该通过图形界面完成设置，并通过解压后双击即可使用的方式分发。

除非确有必要，不要重写已经验证有效的悬浮窗口交互。所有实现都必须优先保证：不抢目标软件焦点、物理键盘正常工作、点击一次只执行一次动作、操作失败时给出明确提示。

## 1. 当前仓库现状

仓库目录：`E:/Projects/FloatPoint`

主要文件：

- `floating_keyboard.py`：PyQt5 实现的象棋悬浮键盘。
- `floating_keyboard_config.json`：位置、透明度、布局等配置。
- `README.md`：当前 Demo 的说明。
- 多个 `.bat` 和 `.vbs` 启动脚本。

当前 Demo 已实现：

1. 14 个中国象棋按钮，每个按钮输出固定的 ASCII 编码，例如 `rb`、`rp`、`bj`。
2. 无边框、置顶、工具窗口。
3. `WS_EX_NOACTIVATE`、`MA_NOACTIVATE` 和 `WindowDoesNotAcceptFocus`，用于尽量避免点击悬浮窗时抢走目标窗口焦点。
4. 使用 Windows 键盘事件向外部窗口发送字符。
5. 自动回车开关。
6. 横排和竖排切换。
7. 透明度调整、拖动、折叠和配置持久化。
8. 通过 Python 和 PyQt5 运行，尚未真正打包为免安装软件。

已知问题：

1. `BUTTON_DEFS` 和 `relayout_buttons()` 将按钮和布局写死在代码中，无法由用户配置。
2. `input_mode` 配置字段目前没有实现多个输入后端，实际只有一种输入方式。
3. `always_on_top` 配置字段目前没有真正控制窗口行为。
4. README 中描述了测试输入框，但当前代码中没有对应功能。
5. 使用的是旧的 `keybd_event`，产品版应优先使用 `SendInput`。
6. `simulate_typing()` 中的 `time.sleep()` 会阻塞 Qt UI，需要改成非阻塞执行。
7. 每 100 ms 记录前台窗口，目标窗口可能被误判；需要提供显式“锁定目标窗口”。
8. `SetForegroundWindow()` 可能重新抢焦点，必须谨慎使用并提供失败处理。
9. 配置写在程序目录，可能遇到只读目录或权限问题。
10. 缺少宏系统、宏录制、布局管理器、按钮编辑器、系统托盘、全局显示/隐藏快捷键、单实例保护和错误日志。
11. 启动脚本依赖用户本机安装 Python、PyQt5 和 pywin32，不满足点击即用要求。

在开始修改前，必须先阅读并理解 `floating_keyboard.py`、`README.md` 和配置文件。不要未经检查就删除现有功能。

## 2. 产品目标

将软件扩展为：

> 用户在任何软件中，都能通过一个不打扰工作的悬浮面板，快速执行自己定义的重复输入动作。

产品必须支持：

- 静态文本输入。
- 单个按键和组合键输入。
- 多步骤宏。
- 宏录制。
- 模板变量。
- 多套键盘布局。
- 布局一键切换。
- 按目标应用自动选择布局。
- 图形化、傻瓜式设置。
- 场景模板和按钮包导入导出。
- Windows 免安装分发。

常见场景包括：

- AI 视觉和数据标注。
- 电商、售后和客服话术。
- 程序员、DevOps 和测试数据输入。
- 财会、人事和行政办公。
- 医疗/HIS 标准化录入。
- 科研、学术和 LaTeX 写作。
- 工控触摸屏、展厅和无障碍辅助。

## 3. 非功能要求

### 3.1 不干扰目标软件

1. 悬浮窗默认不成为前台输入窗口。
2. 点击悬浮按钮后，目标输入框仍然可以接收输入。
3. 物理键盘在正常运行时不受影响。
4. 不安装持续运行的全局键盘钩子。
5. 录制宏时可以临时启用监听，但必须明确显示录制状态，并在停止后立即释放。
6. 需要支持记事本、Word、Excel、浏览器、Labelme 等普通程序。
7. 对管理员权限运行的目标程序，必须检测并提示权限问题，不要静默失败。

### 3.2 稳定性

1. 点击一个按钮只执行一次宏。
2. 宏执行期间 UI 不冻结。
3. 输入失败时显示原因和建议的备用方式。
4. 宏必须支持取消。
5. 必须设置最大步骤数和最大执行时间，防止误配置导致无限执行。
6. 配置文件损坏时自动恢复默认配置，并保留损坏文件备份。
7. 配置写入必须使用临时文件和原子替换。

### 3.3 可维护性

1. UI、动作模型、执行器、配置存储和 Windows API 适配器分层。
2. 领域模型不能直接依赖 PyQt 或 Windows API。
3. 所有配置包含 `schema_version`。
4. 新增按钮包不应修改核心代码。
5. 未来可以实现 macOS 和 Linux 的输入适配器，而无需重写 UI 和按钮包格式。

## 4. 推荐技术路线

### 4.1 当前阶段

推荐使用：

- Python 3.11 或更高版本。
- PySide6 替代 PyQt5，降低后续分发许可风险。
- Windows API `SendInput`。
- `ctypes` 或 pywin32 进行窗口和剪贴板操作。
- PyInstaller 或 Nuitka 打包。

如果暂时不迁移 PySide6，可以先在 PyQt5 上完成架构重构，但必须将 UI 层与领域逻辑隔离，便于后续迁移。

### 4.2 未来跨平台

平台相关实现必须位于独立目录：

```text
platform/windows/
platform/macos/
platform/linux/
```

不能在动作模型中直接调用 `win32api`。macOS 的 Accessibility 权限、Linux X11/Wayland 差异必须在平台适配层处理。

## 5. 领域模型

### 5.1 Action

动作是一个可以被按钮调用的对象。

```json
{
  "id": "mark_and_next",
  "label": "标注并下一张",
  "description": "输入类别、确认并切换到下一张",
  "icon": "check",
  "color": "#3B82F6",
  "steps": [
    { "type": "text", "value": "defect" },
    { "type": "key", "key": "ENTER" },
    { "type": "delay", "ms": 100 },
    { "type": "key", "key": "RIGHT" }
  ],
  "on_error": "stop",
  "confirm": false
}
```

### 5.2 支持的动作步骤

第一阶段必须支持：

- `text`：输入文本。
- `key`：单个按键，例如 `ENTER`、`TAB`、`RIGHT`。
- `hotkey`：组合键，例如 `CTRL+S`、`CTRL+V`。
- `delay`：等待指定毫秒。
- `paste`：写入剪贴板并粘贴。
- `variable`：插入变量值。

第二阶段可以支持：

- `repeat`：重复一组步骤。
- `condition`：基于目标窗口或变量判断。
- `mouse`：鼠标移动和点击，必须明确提示坐标宏的不稳定性。

### 5.3 变量

第一阶段支持：

- `{{clipboard}}`：当前剪贴板文本。
- `{{date}}`：当前日期。
- `{{time}}`：当前时间。
- `{{counter}}`：递增计数器。
- `{{app_name}}`：目标应用名称。

变量必须通过界面插入，普通用户不需要手写模板语法。

### 5.4 Button

按钮只引用动作，不直接保存执行逻辑。

```json
{
  "id": "red_bing",
  "label": "红兵",
  "action_id": "type_rb",
  "icon": "兵",
  "color": "#E53935",
  "tooltip": "输入 rb"
}
```

### 5.5 Layout

布局必须可保存、可导入和可切换。

```json
{
  "id": "annotation",
  "name": "图片标注",
  "orientation": "horizontal",
  "rows": 2,
  "columns": 7,
  "buttons": [
    { "button_id": "red_bing", "row": 0, "column": 0 },
    { "button_id": "red_cannon", "row": 0, "column": 1 },
    { "button_id": "black_bing", "row": 1, "column": 0 }
  ],
  "settings": {
    "opacity": 0.93,
    "show_labels": true,
    "button_size": "compact"
  }
}
```

### 5.6 Profile

Profile 用于根据目标应用自动选择布局。

```json
{
  "process": "labelme.exe",
  "window_title_contains": "",
  "layout_id": "annotation"
}
```

## 6. 动作执行架构

推荐模块：

```text
domain/
  action.py
  button.py
  layout.py
  profile.py

application/
  action_executor.py
  target_manager.py
  macro_recorder.py
  layout_manager.py

platform/windows/
  send_input.py
  window_manager.py
  clipboard.py
  global_hotkey.py
```

执行流程：

```text
用户点击按钮
  -> TargetManager 获取或验证目标窗口
  -> ActionStore 读取动作
  -> ActionExecutor 创建执行队列
  -> WindowsInputInjector 执行每一步
  -> UI 显示进度、成功或失败
```

执行器必须是非阻塞的。不要在 UI 线程中用长时间 `sleep()`。可以使用 `QTimer`、异步队列或后台任务，并通过信号通知 UI。

执行器还必须支持：

- 开始。
- 暂停。
- 取消。
- 超时。
- 失败停止。
- 失败后继续。
- 执行日志。

## 7. 目标窗口设计

提供三种目标模式：

1. **自动目标**：使用最近的外部前台窗口。
2. **锁定目标**：用户点击“锁定目标”，固定发送到某个窗口。
3. **应用绑定**：根据进程名和窗口标题自动选择布局和目标。

主界面必须显示当前状态，例如：

```text
目标：Labelme.exe
状态：已锁定
```

目标失效时必须显示错误，不得静默丢失输入。

不要把 `SetForegroundWindow()` 作为默认解决方案。优先保持当前焦点，并只在明确的备用策略中使用激活窗口。

## 8. 宏录制功能

### 用户流程

1. 点击“添加按钮”。
2. 填写按钮名称。
3. 点击“开始录制”。
4. 用户在目标软件中输入文字、按键或组合键。
5. 点击“停止录制”。
6. 显示步骤列表。
7. 用户可以删除、排序和修改步骤。
8. 点击“测试”。
9. 保存到当前布局。

### 录制要求

- 录制时必须有明显的红色“录制中”状态。
- 必须提供暂停和取消。
- 录制过程中不应记录悬浮键盘自身的按钮点击。
- 停止录制后立即释放监听。
- 默认不录制鼠标，鼠标录制放到高级设置。
- 自动合并连续字符，避免生成大量单字符步骤。
- 连续按键之间的延迟可以自动估算，但用户必须可以修改。

## 9. 傻瓜式设置界面

### 首次启动向导

第一步：选择场景模板。

```text
[图片标注] [客服话术] [程序员]
[办公录入] [LaTeX] [空白键盘]
```

第二步：选择布局。

```text
[横向紧凑] [纵向侧栏] [大按钮触屏]
```

第三步：测试目标窗口。

第四步：完成。

### 添加按钮向导

按钮编辑器必须提供：

- 按钮名称。
- 显示文字。
- 图标或符号。
- 颜色。
- 动作类型。
- 录制宏。
- 测试动作。
- 是否需要确认。
- 是否自动回车。

普通用户不需要编辑 JSON。高级 JSON 编辑可以作为可选功能，但不能成为主要配置路径。

### 布局管理

必须支持：

- 新建布局。
- 复制布局。
- 重命名布局。
- 删除布局。
- 拖动按钮排序。
- 一键切换布局。
- 导入和导出布局。
- 设置应用绑定。

- 搜索按钮。

- 紧急停止宏快捷键。
- 执行中的动作状态提示。
- 失败时的明确错误提示。
- 高 DPI 和多显示器适配。
- 贴边和吸附。
- 透明度和按钮尺寸设置。

## 11. 按钮包和导入导出

按钮包用于分享场景配置，建议扩展名为 `.qipack`。

包内包含：

```text
manifest.json
actions.json
layouts.json
icons/
README.md
```

必须校验：

- `schema_version`。
- ID 是否重复。
- 动作类型是否支持。
- 步骤参数是否合法。
- 图标路径是否越界。
- 是否包含危险动作。

导入失败时不能破坏现有配置。

## 12. 配置、日志和数据安全

建议目录：

```text
%AppData%/QuickInput/config.json
%AppData%/QuickInput/packs/
%AppData%/QuickInput/backups/
%AppData%/QuickInput/logs/
```

要求：

1. 配置自动备份。
2. 配置写入采用临时文件和原子替换。
3. 默认只记录错误和动作 ID，不记录用户输入的敏感文本。
4. 默认不联网、不上传内容、不记录键盘历史。
5. 剪贴板内容使用后尽量恢复原内容。
6. 医疗、财务和客服模板必须支持本地运行。

```text
QuickInput/
  QuickInput.exe
  packs/
  resources/
  README.txt
```

用户解压后双击 `QuickInput.exe` 即可使用，不依赖 Python、PyQt5 或 pywin32。

要求：

- 提供无控制台窗口版本。
- 提供调试日志版本。
- 程序启动目录不能依赖当前工作目录。
- 使用单实例互斥锁。
- 关闭窗口时不应残留后台进程。
- 配置不能写入程序安装目录。
- 处理 Windows Defender 或打包误报的基本说明。

暂不强制要求单文件 EXE。单文件版本可以作为后续发布形式。

## 16. 验收标准

完成后必须满足：

1. 用户无需编辑代码即可创建按钮。
2. 用户可以录制至少包含文本、Enter、Tab 和组合键的宏。
3. 用户可以把多个步骤保存为一个动作。
4. 用户可以在至少三套布局之间一键切换。
5. 用户可以将布局绑定到目标应用。
6. 点击按钮时目标软件通常不会丢失焦点。
7. 物理键盘在正常运行期间仍然可用。
8. 宏执行期间悬浮窗口不会卡死。
9. 宏可以被取消，并有紧急停止方式。
10. 原有象棋输入功能保持可用。
11. 用户可以导入和导出按钮包。
12. 程序可以在没有 Python 的 Windows 电脑上启动。
13. 配置损坏时不会导致程序无法启动。
14. 至少完成一组自动化测试和一组真实软件手工测试。
