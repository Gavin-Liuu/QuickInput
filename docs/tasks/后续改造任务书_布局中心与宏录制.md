## 2. 目标界面结构

### 2.1 主悬浮面板

主面板必须改成以下结构：

```text
┌──────────────────────────────────────────────┐
│ [搜索] [当前布局下拉框]              Windows 标题栏 │
├──────────────────────────────────────────────┤
│                                              │
│              当前布局的按钮网格               │
│                                              │
├──────────────────────────────────────────────┤
│  [透明度滑块]                 [目标：xxx / 锁定] │
└──────────────────────────────────────────────┘
```

要求：

1. 删除主界面中“快捷输入”四个字及其占用的标题标签。
2. 搜索按钮移动到原“快捷输入”所在的左侧区域，成为主面板左上角的第一个功能控件。
3. 搜索按钮点击后展开当前布局的搜索输入框；搜索框必须可以输入文本。打开搜索时允许面板临时获取焦点，关闭搜索后恢复不抢焦点状态。
4. 删除底部“执行完成”或类似完成状态文字。不要在主面板底部保留持久化执行完成状态。
5. 底部只保留透明度控制和目标窗口控制。宏执行中的停止按钮可以临时出现，但动作结束后不得显示“执行完成”。
6. 透明度控制放回主面板，控制当前布局的透明度并立即应用到窗口。
7. 透明度调节后必须保存到当前布局，而不是只保存到全局窗口设置。
8. 删除自定义的半最小化、隐藏、关闭按钮。不要在自定义内容区重复绘制 Windows 标题栏功能。
9. 使用 Windows 原生标题栏提供最小化、最大化和窗口关闭行为。
10. 如果产品决定不显示 Windows 原生关闭按钮，应使用明确的 Qt 窗口标志验证，而不是绘制假的关闭按钮。程序退出必须通过系统托盘右键菜单完成。
11. 系统托盘右键菜单必须有清晰的“退出程序”菜单项；退出时注销全局热键、停止录制器、停止宏线程、保存配置并退出 Qt 事件循环。
12. 托盘左键可以显示/隐藏面板，但不能代替右键退出功能。
13. 继续使用 Windows 原生边框处理缩放。不要重新引入自定义 `WM_NCHITTEST`，否则会再次拦截按钮点击。

### 2.2 窗口行为

- 普通面板操作继续使用 `WS_EX_NOACTIVATE`，不抢目标软件焦点。
- 搜索输入是明确的例外状态，打开搜索后才允许键盘输入到搜索框。
- Windows 原生最小化后应进入任务栏/系统窗口状态，不应只是隐藏按钮网格。
- 托盘隐藏是独立行为，由托盘或全局快捷键控制。
- 关闭窗口后的行为必须明确记录在 README：建议 native close 仅隐藏到托盘，真正退出使用托盘右键“退出程序”。如果采用真正关闭，则必须保证托盘菜单仍能退出并且不残留进程。

## 3. 设置中心的新层级

当前设置中心把布局选择、布局操作、按钮动作、应用绑定分散在多个顶级页签中。需要重组为“布局与按钮”中心。

### 3.1 顶级页面

设置中心建议只保留：

1. `布局与按钮`：全部布局、按钮、动作、应用绑定配置。
2. `常规与诊断`：全局快捷键、日志、备份、恢复和诊断。

不要再把“场景向导”“布局管理”“按钮与宏编辑”“应用自动绑定”作为互相割裂的主要页签。

### 3.2 布局与按钮页面

“先选择一个布局，再直接编辑这个布局里的按钮……”这段说明、当前布局下拉框、新建布局、复制布局、重命名布局、删除布局，全部移动到“布局与按钮”页面内部。

推荐界面：

```text
布局与按钮
┌──────────────────────────────────────────────────────────┐
│ 当前布局 [中国象棋（横排）▼] [新建] [复制] [重命名] [删除] │
├─────────────────────────┬────────────────────────────────┤
│ 布局预览                 │ 选中按钮属性和动作              │
│                         │                                │
│ [兵] [炮] [马] [车]      │ 按钮名称                        │
│ [卒] [炮] [马] [车]      │ 显示文字                        │
│                         │ 颜色、图标、提示                 │
│ 点击按钮即可选中编辑     │ 宏步骤                           │
│                         │ [录制宏] [添加文本] [添加按键]    │
│                         │ 应用绑定                         │
└─────────────────────────┴────────────────────────────────┘
```

要求：

1. 左侧预览尽量复用主面板的按钮渲染逻辑，而不是再实现一套完全不同的按钮显示。
2. 点击预览中的按钮，右侧显示该按钮的属性和动作步骤。
3. 用户可以在预览中拖动按钮交换位置，或通过网格槽位操作调整顺序。
4. 用户不需要看到或填写按钮唯一 ID。
5. 右侧动作编辑、宏录制和应用绑定都属于当前布局上下文。
6. 应用绑定规则必须在当前布局页内配置：例如“当前目标应用 -> 使用当前布局”。
7. “动作结束后发送 Enter”和“执行前确认”必须显示在布局设置区，而不是按钮属性区。

### 3.3 新建布局流程

点击“新建布局”后打开一个向导或对话框：

1. 输入布局名称。
2. 选择横向/纵向排列。
3. 设置行数和列数。
4. 设置默认按钮尺寸。
5. 确认后创建布局。

创建完成后，界面必须立即显示对应行列的预览网格。每个空槽位都显示一个可点击的预设按钮，例如：

```text
[按钮 1] [按钮 2] [按钮 3]
[按钮 4] [按钮 5] [按钮 6]
```

用户点击任意预设按钮后，可以直接设置：

- 按钮显示文字。
- 图标或符号。
- 颜色。
- 悬浮提示。
- 文本动作。
- 单键动作。
- 组合键动作。
- 多步骤宏。
- 是否需要确认不能在这里设置，确认属于布局级设置。
- 是否自动 Enter 不能在这里设置，自动 Enter 属于布局级设置。

如果用户删除按钮，预览中应显示空槽位和“添加按钮”入口，而不是留下无法点击的空白对象。

## 4. 布局级动作默认值

用户明确要求：

- 动作结束后发送 Enter：针对布局。
- 执行前确认：针对布局。

### 4.1 领域模型

扩展 `LayoutSettings`：

```python
@dataclass
class LayoutSettings:
    opacity: float = 0.95
    show_labels: bool = True
    button_size: str = "compact"
    always_on_top: bool = True
    auto_enter_default: bool = False
    confirm_before_action: bool = False
```

`auto_enter_default` 和 `confirm_before_action` 的值由当前布局控制。

### 4.2 兼容策略

旧数据中可能存在：

- `Button.auto_enter`
- `Action.auto_enter`
- `Action.confirm`
- 全局 `window.auto_enter`

迁移策略：

1. 加载旧配置时，如果布局没有布局级设置，则优先从旧全局设置迁移到当前布局。
2. 如果旧按钮或动作设置为 `true`，迁移时可以将对应布局的默认值设置为 `true`，但不能继续在新 UI 中显示按钮级开关。
3. 新版本执行逻辑只读取当前布局的设置。
4. 保留旧字段的反序列化能力，避免旧 `.qipack` 无法导入；保存新格式时可以不再写入按钮级字段。

### 4.3 执行流程

主面板点击按钮时：

1. 获取当前布局。
2. 如果布局设置了 `confirm_before_action`，执行动作前弹出确认。
3. 将布局的 `auto_enter_default` 传给执行器。
4. 执行器在动作步骤结束后追加 Enter。
5. 不再从按钮读取 `auto_enter`。
6. 执行完成后不在主面板显示持久化“执行完成”文本。

## 5. 按钮管理逻辑重构

当前代码仍有全局 `LayoutManager.buttons` 字典，按钮通过全局 ID 管理。用户已经明确要求按布局管理按钮，因此需要把全局字典降级为兼容层。

### 5.1 推荐模型

新代码应该以布局内按钮为主：

```python
@dataclass
class LayoutButton:
    label: str
    action: Action
    icon: str = ""
    color: str = "#1976D2"
    tooltip: str = ""

@dataclass
class LayoutButtonSlot:
    row: int
    column: int
    button: LayoutButton | None
```

如果实现成本过高，第一阶段可以保留内部存储 ID，但必须：

- ID 自动生成。
- ID 对用户不可见。
- UI 只通过 `layout.get_button_at(row, column)` 或 `layout.buttons[index]` 操作。
- 不允许用户编辑按钮 ID。
- 不允许设置中心展示 `button_id`。
- 复制布局时深拷贝按钮和动作。

### 5.2 重要行为

- 新建布局的按钮必须属于新布局。
- 复制布局后，修改副本的按钮属性不能改变原布局。
- 删除布局时清理仅被该布局使用的内部按钮/动作对象，或由垃圾回收式存储策略统一处理。
- 导入旧按钮包时转换到布局上下文。
- 导出按钮包时仍可以输出兼容的 `buttons.json` 和 `actions.json`。

## 6. 宏录制问题调查与修复方案

### 6.1 当前实现的已知风险

当前 `application/macro_recorder.py` 使用 Windows `WH_KEYBOARD_LL` 全局低级键盘钩子，并有以下风险：

1. 监听整个系统键盘，没有严格限定到用户选定的目标窗口。
2. `own_hwnds` 只过滤已注册窗口；当前面板、设置窗口和录制器窗口可能没有全部注册。
3. 字符转换是固定 US 键盘布局映射，使用 `_vk_to_char()`，不能可靠处理用户当前键盘布局、中文输入法、死键和特殊 Unicode 字符。
4. 键盘自动重复可能被记录为多个相同按键或重复字符。
5. 修饰键使用集合和字典排序，组合键顺序不稳定，也没有完整处理 Shift、左右 Ctrl、左右 Alt。
6. Shift 加功能键、AltGr、国际键盘布局等情况可能被识别错误。
7. 停止录制或窗口关闭时，必须确保 hook 线程、钩子句柄和修饰键状态全部释放。
8. 录制时点击工作台按钮或设置窗口，可能造成不应出现的输入步骤或目标窗口变化。
9. 录制器没有明确的“锁定录制目标”流程，用户切换到其他程序可能把其他程序的操作一起录入。
10. 录制宏后测试运行使用当前目标窗口，可能与录制时的目标窗口不一致。

### 6.2 推荐录制流程

录制宏必须变成显式的三步流程：

1. 用户点击“选择录制目标”。
2. 用户点击目标软件窗口，程序保存目标窗口句柄、进程 ID 和窗口标题。
3. 用户点击“开始录制”。
4. 录制器只接受来自目标窗口的键盘事件。
5. 用户点击“停止录制”。
6. 程序停止 hook 并释放所有资源。
7. 预览步骤，用户确认后保存到当前布局的当前按钮。

录制界面必须明确显示：

```text
录制目标：notepad.exe - 无标题
状态：未录制 / 正在录制 / 已暂停 / 已停止
```

### 6.3 目标窗口过滤

在开始录制前记录：

- `target_hwnd`
- `target_pid`
- `target_process_name`

每个低级键盘事件到来时：

1. 查询当前前台窗口。
2. 如果当前前台窗口是录制器、设置中心或主面板，丢弃事件。
3. 如果当前前台窗口不是 `target_hwnd`，默认丢弃事件，并在 UI 提示“已切换离开录制目标”。
4. 可选高级模式：允许同一进程的子窗口录制，但必须通过 PID 判断，而不是只比较窗口标题。

不要仅使用 `own_hwnds` 作为唯一过滤条件。

### 6.4 字符解析

不要继续只使用固定 `_vk_to_char()`。

优先方案：

- 使用 `GetKeyboardState` 获取当前修饰键状态。
- 使用 `MapVirtualKeyEx` 和 `ToUnicodeEx` 根据当前键盘布局转换字符。
- 正确处理死键、Shift、Ctrl、Alt、AltGr 和国际键盘布局。
- 中文输入法场景要明确策略：默认只录制物理按键动作，不能假装能够还原任意输入法组合后的中文文本。

对中文或复杂文本，增加两种可选模式：

1. `按键录制`：记录实际键盘按键和组合键。
2. `文本捕获`：用户在录制器中粘贴或输入一段文本，保存为 `text`/`paste` 步骤。

### 6.5 事件合并

录制器需要：

- 连续可打印字符合并成一个 `text` 步骤。
- 连续空格按配置合并。
- 功能键生成 `key` 步骤。
- Ctrl/Alt/Win 组合生成一个 `hotkey` 步骤。
- 忽略键盘自动重复，除非用户明确开启“记录重复按键”。
- 延迟只在超过阈值时生成 `delay`，并设置最大值。
- 录制暂停时清空修饰键状态，避免恢复后出现伪组合键。
- `stop()`、`cancel()` 和窗口关闭都必须释放 hook。

### 6.6 宏录制测试

至少新增以下测试：

1. 目标窗口外的按键不会被记录。
2. 录制器和设置窗口的按键不会被记录。
3. 连续文本会合并成一个步骤。
4. Ctrl+S、Ctrl+Shift+P、Alt+Tab 等组合键步骤稳定。
5. Shift 加标点符号按当前布局转换。
6. 自动重复按键不会生成重复步骤。
7. 停止和取消后 hook 线程退出且状态复位。
8. 暂停恢复不会遗留修饰键状态。
9. 录制目标失效时给出明确提示并停止录制。
10. 录制后保存的动作可以在测试注入器中完整重放。

真实 Windows 手工测试至少覆盖：

- 记事本。
- Word 或浏览器文本框。
- 中文输入法开启和关闭两种状态。
- 英文键盘和当前系统实际键盘布局。
- 录制时切换到其他窗口。
- 目标程序以管理员权限运行的场景。

## 7. 配置格式与迁移

配置 `schema_version` 至少升级到 2。

迁移要求：

1. 旧配置可以正常启动。
2. 旧象棋包可以正常显示和输入。
3. 旧全局透明度迁移到活动布局。
4. 旧全局自动回车迁移到活动布局的 `auto_enter_default`。
5. 旧按钮/动作确认和自动回车迁移到对应布局默认值。
6. 迁移失败时备份原配置并恢复默认，不得启动崩溃。
7. 导入旧 `.qipack` 时保持旧格式兼容，导出时写入新的布局级字段。

建议保存结构：

```json
{

      "orientation": "horizontal",

        "opacity": 0.93,
        "button_size": "compact",
        "always_on_top": true,
        "auto_enter_default": true,
        "confirm_before_action": false
      },
      "buttons": []
    }
  }
}
```
